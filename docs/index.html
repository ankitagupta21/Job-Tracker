Built for how job searches actually work

No manual data entry. No spreadsheets falling out of sync with reality.

✉

Automatic Gmail scanning

Runs on a schedule, searches your inbox for application-related emails, and skips anything it's already seen.

🧠

Local AI classification

Uses Ollama running on your own machine to read each email and detect status changes — nothing sent to a third-party API.

📊

Full status timeline

Every status change is logged with a history, so you can see exactly when an application moved from Applied to Interview to Offer.

🗑

Trash, not delete

Removed an application by mistake? It's recoverable in Trash, not gone forever.

🔒

Self-hosted & private

Your data lives in a Postgres database on your own machine. No cloud account, no third party sees your inbox.

🛠

Open source

Spring Boot, React, Kafka, and Postgres under the hood. Inspect it, modify it, extend it.

# 1. Clone the repo git clone https://github.com/ankitagupta21/Job-Tracker.git cd Job-Tracker # 2. Configure your environment cp .env.example .env # edit .env with your DB password, etc. # 3. Start everything docker compose up -d --build # Dashboard: http://localhost:3000 # API: http://localhost:8080
Note: the dashboard and manual application tracking work fine out of the box with just Docker and Git. To get automatic Gmail scanning, you'll also need: a Google Cloud OAuth credentials.json for your own Gmail account, placed at ~/.job-tracker/credentials.json; and Ollama installed and running locally with a model pulled (e.g. ollama pull llama3). Without these, scanned emails just sit unclassified — the rest of the app still works.
Linux users: Ollama connectivity currently relies on Docker Desktop's host.docker.internal DNS name, which native Docker Engine on Linux doesn't resolve by default. You'll need to add extra_hosts: ["host.docker.internal:host-gateway"] to the backend service in docker-compose.yml for AI classification to reach Ollama.
